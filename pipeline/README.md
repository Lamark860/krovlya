# pipeline — выгрузка → каталог → YML-фиды

Чистый Python 3, без внешних зависимостей. Два шага, запускаются из корня проекта.

```bash
python3 pipeline/build_catalog.py            # docs/catalog.csv → data/catalog.json
python3 pipeline/build_feed.py               # data/catalog.json → data/feeds/*.yml
```

Первый шаг можно запустить на другом файле: `python3 pipeline/build_catalog.py путь/к/выгрузке.csv`.

## Что делает шаг 1 (build_catalog.py)

- Берёт только включённые товары двух рекламных направлений.
- Отбрасывает непригодное для рекламы: без цены, без фото, «2 СОРТ».
- Нормализует грязь выгрузки: единицы измерения (`м2`, `Квадратный метр` → `м²`),
  форматы (`600x1200`, `1200х600`, `600х1200х9` → `600×1200`), бренды.
- Собирает URL картинок из имён файлов по схеме `/pictures/product/big/{имя}_big.{ext}`.
- Готовит `id` оффера: без пробелов и кавычек, не длиннее 100 символов, уникальный.
  Преобразование детерминированное — тот же артикул всегда даёт тот же id,
  иначе Директ посчитает офферы новыми и обнулит статистику.
- Считает **свою** группировку товаров (см. ниже).

## Почему группы считаем сами

В выгрузке два параллельных дерева категорий: корень «Керамогранит» и он же внутри
«Плитки и керамогранита». Если брать категории магазина как есть, часть товаров уйдёт
в Директ дважды. Поэтому группа и подгруппа вычисляются из категории + свойств товара:

```
Плитка и керамогранит          Напольные покрытия
├── Керамогранит               ├── Ламинат
│   ├── Крупноформат 600×1200+ │   ├── 32 / 33 / 34 класс
│   ├── 600×600                │   └── Другие серии
│   └── Другие форматы         ├── Кварцвинил и ПВХ
└── Керамическая плитка        │   ├── 41 / 42 / 43 / 44 класс
    └── Мелкоформатная плитка  │   └── Другие серии
                               ├── Кварцевый паркет
                               ├── Паркетная доска
                               └── Подложка и комплектующие
```

Эти узлы становятся категориями фида — по ним в Директе делятся товарные кампании.

## Ручные перебивки

`pipeline/overrides.json` — правки поверх выгрузки, ключ **артикул товара**:

```json
{
  "EPL168-Large 833 4V": {
    "name": "Ламинат Egger Pro Large 33 класс, влагостойкий",
    "pictures": ["https://…/своё-фото.jpg"]
  }
}
```

Нужны потому, что источник данных — выгрузка из AdvantShop: без перебивок любая наша
ручная правка названия или фото затрётся при следующем обновлении каталога.

## Обновление данных

1. Выгрузить свежий CSV из админки AdvantShop, положить в `docs/catalog.csv`.
2. Прогнать оба шага.
3. Сверить отчёт: сколько товаров добавилось и исчезло, у скольких изменилась цена.

Файлы `data/` не коммитятся — это артефакты сборки, они пересоздаются из выгрузки.
