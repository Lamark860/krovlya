# pipeline — выгрузка → каталог → YML-фиды

Чистый Python 3, без внешних зависимостей. Шаги запускаются из корня проекта
**в этом порядке**:

```bash
python3 pipeline/build_catalog.py            # docs/catalog.csv → data/catalog.json
python3 pipeline/build_feed.py               # data/catalog.json → data/feeds/*.yml
python3 pipeline/build_showcase.py           # → витрина и данные квиза внутрь site/
python3 pipeline/fetch_images.py             # фото витрины → WebP в site/public/showcase/
python3 pipeline/fetch_images.py --catalog plitka --limit 300   # фото верха каталога
python3 pipeline/build_catalog_page.py       # → данные страниц каталога
```

Первый шаг можно запустить на другом файле: `python3 pipeline/build_catalog.py путь/к/выгрузке.csv`.

Шаги 3 и 4 требуют друг друга: витрина ставит локальный путь к фото, только если файл
уже скачан, а скачивает их последний шаг. Значит, при **первом** прогоне на новой выгрузке
шаг 3 нужно повторить после шага 4 — иначе новые позиции останутся со ссылками на фото
сайта магазина, и лендинг будет зависеть от того, жив ли сейчас чужой сайт.
Для `fetch_images.py` нужен `cwebp` (`brew install webp`).

## Что делает шаг 1 (build_catalog.py)

- Берёт только включённые товары двух рекламных направлений.
- Отбрасывает непригодное для рекламы: без цены, без фото, «2 СОРТ».
- Нормализует грязь выгрузки: единицы измерения (`м2`, `Квадратный метр` → `м²`),
  форматы (`600x1200`, `1200х600`, `600х1200х9` → `600×1200`), бренды.
- Собирает URL картинок из имён файлов по схеме `/pictures/product/big/{имя}_big.{ext}`.
- Готовит `id` оффера: без пробелов и кавычек, не длиннее 100 символов, уникальный.
  Преобразование детерминированное — тот же артикул всегда даёт тот же id,
  иначе Директ посчитает офферы новыми и обнулит статистику.
- Считает **свою** группировку товаров (см. ниже).

## Почему группы считаем сами

В выгрузке два параллельных дерева категорий: корень «Керамогранит» и он же внутри
«Плитки и керамогранита». Если брать категории магазина как есть, часть товаров уйдёт
в Директ дважды. Поэтому группа и подгруппа вычисляются из категории + свойств товара:

```
Плитка и керамогранит            Напольные покрытия
├── Керамогранит                 ├── Ламинат
│   ├── Крупноформат 600×1200+   │   ├── 32 / 33 / 34 класс
│   ├── 600×600                  │   └── Другие серии
│   ├── Мелкий формат            ├── Кварцвинил и ПВХ
│   └── Другие форматы           │   ├── 41 / 42 / 43 / 44 класс
└── Керамическая плитка          │   └── Другие серии
    ├── Мелкий формат            ├── Кварцевый паркет
    ├── Крупноформат 600×1200+   ├── Паркетная доска
    ├── 600×600                  └── Подложка и комплектующие
    └── Другие форматы
```

Эти узлы становятся категориями фида — по ним в Директе делятся товарные кампании,
и они же дают слаги для адресов вида `/catalog-plitka?group=keramogranit&sub=600x600`.

**Группа плитки берётся из названия товара, а не из категории магазина.** Категории
у клиента набиты по формату, поэтому в «Керамограните» лежали 63 товара с названием
«Керамическая плитка», а в «Керамической плитке» — 24 керамогранита. Для объявления
«купить керамогранит» это прямое несовпадение. Если название материал не называет
(бывает: «Centro», «Berlin»), остаёмся на категории магазина. «Грес» и «гранит
керамический» — тот же керамогранит, только словами поставщика.

Названия заодно чистятся от мусора учётной системы: ведущий артикул
(`GT60601503MR Плитка грес глаз. Anima_GT Белый 60*60 _ 1 \43,2`), хвост с количеством
в упаковке, сокращения. У полов такого нет вовсе, у плитки — 102 и 125 позиций.

## Что считается товаром, а что сопутствующим

`pipeline/filters.py` — одно правило на всех, кто строит выборки для сайта:
страница каталога и данные квиза. Разъедься они — и счётчик в квизе начнёт обещать
позиции, которых в каталоге нет, а мы обещаем, что число честное.

- `is_product()` отсекает сопутствующее по названию: подложки, затирки, клей,
  грунтовки, крестики и клинья. Сортировка идёт по цене, и без этого каталог
  плитки открывался клиньями по 78 ₽ и мешком клея. «Клин» и «клинкер» разведены
  границей слова: клинкер — это плитка.
- `drop_piece_decor()` убирает штучный декор, который в списке по цене выглядит
  как дешёвая плитка: первым стоял «Octagon Taco 4,6×4,6» за 54 ₽. Порог не выдуман,
  а взят из самих данных — дешевле самой дешёвой метровой позиции направления
  цена за метр быть не может.

## Ручные перебивки

`pipeline/overrides.json` — правки поверх выгрузки, ключ **артикул товара**:

```json
{
  "EPL168-Large 833 4V": {
    "name": "Ламинат Egger Pro Large 33 класс, влагостойкий",
    "pictures": ["https://…/своё-фото.jpg"]
  }
}
```

Нужны потому, что источник данных — выгрузка из AdvantShop: без перебивок любая наша
ручная правка названия или фото затрётся при следующем обновлении каталога.

## Обновление данных

1. Выгрузить свежий CSV из админки AdvantShop, положить в `docs/catalog.csv`.
2. Прогнать все шаги в порядке из начала файла.
3. Сверить отчёт: сколько товаров добавилось и исчезло, у скольких изменилась цена.

Файлы `data/` не коммитятся — это артефакты сборки, они пересоздаются из выгрузки.

## Данные для страницы каталога

`build_catalog_page.py` — после `build_catalog.py` и `fetch_images.py`:

```
python3 pipeline/build_catalog_page.py
```

Кладёт `site/public/data/catalog-{poly,plitka}.json` — компактные записи, из которых
страницы `/catalog` и `/catalog-plitka` рисуют карточки на клиенте. Сортировка по цене,
сопутствующее и штучный декор отсеяны (см. выше). Единица измерения переносится как есть:
пустую **не заменяем на «м²»**, иначе цена за упаковку выглядит как цена за метр.

## Фото каталога

По умолчанию `fetch_images.py` качает только витрину лендингов — 32 товара.
Режим `--catalog <направление> --limit N` берёт верх выдачи каталога: он отсортирован
по цене, и до кнопки «Показать ещё» человек видит первые два-три десятка.

```
python3 pipeline/fetch_images.py --catalog plitka --limit 300
```

Зачем: каталог — рекламная посадочная, а 98 % его карточек грузили картинку
с moiremont18.ru, который сам заказчик называет сломанным (вопрос 55).
Скачано 299 файлов ≈ 18 МБ; остальные 2 350 позиций плитки тянут фото оттуда же.
После скачивания обязательно перегенерировать данные страницы — локальный путь
подставляет `build_catalog_page.py`, а не сам загрузчик.
